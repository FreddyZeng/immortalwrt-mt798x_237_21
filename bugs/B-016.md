# B-016: init.d/eqos cleanup_loadbalance_rules 内 grep 前缀匹配 Bug

<!-- BID: B-016 | FID: F-QOS01 | CID: C-FQOS01-13 -->

## 症状
多 WAN 场景（pppoe-wan + pppoe-wan2）执行 `eqos stop` 或重建规则时，
`cleanup_loadbalance_rules()` 可能以错误的 `ipaddr`（pppoe-wan2 的网关）
来删除 pppoe-wan 的 iptables PREROUTING 规则，导致：
- pppoe-wan 的清理规则残留（路由表污染）
- pppoe-wan2 的规则被误删

## 根因

`init.d/eqos` `cleanup_loadbalance_rules()` L30（f90dab52bb 引入）：

```sh
# ❌ Bug 代码
ipaddr=$(ip route show | grep default | grep "$var" | awk '{print $3}' | head -1)
```

当 `$var="pppoe-wan"` 时，`grep "pppoe-wan"` 同时匹配 `pppoe-wan2` 的路由条目，
取到错误的网关 IP。

B-015 修复了 `loadbalance` 脚本中的同类 Bug，但漏掉了 `init.d/eqos` 中的此处。

## 修复

```sh
# ✅ 修复后：精确接口匹配
ipaddr=$(ip route show default dev "$var" 2>/dev/null | awk '{print $3}' | head -1)
log_debug "[EQOS-B016-01] cleanup_loadbalance_rules: iface=$var gateway=$ipaddr"
```
