# B-014: TProxy/SSR Plus mark 0x8000 冲突 + DHCP hotplug 安装竞争

<!-- BID: B-014 | FID: F-QOS01 | CID: C-FQOS01-11 -->

## 症状

1. **TProxy 冲突**：`loadbalance` 和 `eqos add` 的 PREROUTING CONNMARK mark/restore-mark 规则缺少  
   `-m mark ! --mark 0x8000/0x8000` 保护，导致 SSR Plus TProxy 拦截的 UDP 流量被 HNAT 硬件加速  
   旁路，SSR Plus 透明代理失效。

2. **DHCP hotplug 安装噪声**：`install_dhcp_hotplug()` 每次 eqos start 都无条件覆盖  
   `/etc/hotplug.d/dhcp/99-eqos`，即使内容不变也写入，与 dnsmasq 重建竞争。

3. **IPv6 fallback mark 顺序**：`--mark 0 → mark=2/34` fallback 规则安装在  
   `iptables_start_inital()` 内（会被后续 `ip6tables -F eqos` 清除），而非在 `config_foreach`  
   之后追加。

4. **WAN 接口 hotplug 死循环**：`iface/10-eqos` 对所有接口事件触发 `eqos start`，  
   包括 loopback、lan、iptv、zerotier，导致不相关接口变化反复重建 mangle 规则。

## 根因

- TProxy 保护：规则中缺少 `-m mark ! --mark 0x8000/0x8000` bit 15 掩码守卫  
- hotplug 幂等：安装前未对比文件内容（`cmp -s`）  
- IPv6 fallback：放置位置在 chain flush 之前  
- 接口过滤：未限定触发接口范围

## 修复

| 问题 | 修复方法 |
|------|---------|
| TProxy bit 15 冲突 | 所有 PREROUTING NEW mark 规则添加 `-m mark ! --mark 0x8000/0x8000` |
| DHCP hotplug 幂等 | `install_dhcp_hotplug()` 使用 `cmp -s` 比对后再决定是否覆盖 |
| IPv6 fallback 顺序 | 移至 `config_foreach parse_device` 之后用 `-A eqos` 追加 |
| 接口触发过滤 | `iface/10-eqos` 仅处理 `eqos.config.interface` 列表内的接口 up 事件 |
