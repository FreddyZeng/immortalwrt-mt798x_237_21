# B-017: tproxy_protection_v4 对 UNBIND FOE 执行 memset 破坏 hash 碰撞连接

<!-- BID: B-017 | FID: F-QOS01 | CID: C-FQOS01-14 -->

## 症状

浏览器连接某个 URL 后**偶发**短时间无响应，立即打开新 URL 则立即恢复。

## 根因

`mtk_hnat_tproxy_protection_v4` 对所有带 `mark & 0x8000` 的 TCP/UDP 包，**无论 FOE 状态是 BIND 还是 UNBIND，都执行 `memset(entry, 0)`**。

### 核心逻辑谬误

注释已正确指出：
> "TPROXY flows go to LOCAL_IN, so HNAT hardware can never BIND them through the normal FORWARD/POSTROUTING path."

**但代码仍然对 UNBIND 执行 memset——这自相矛盾：**

既然 TPROXY 流量走 LOCAL_IN，永远不经过 POSTROUTING，HNAT 永远无法 BIND 它们，那 TPROXY 流量的 FOE slot **永远是 UNBIND 状态**。对 UNBIND entry 执行 memset 清零没有任何意义。

### hash 碰撞破坏直连连接

FOE slot 由 5-tuple hash 分配。TPROXY 流量的 SYN 和**其他直连（非代理）连接**可能 hash 到**同一个 FOE slot**。

当直连连接正在积累流量、试图从 UNBIND 到达 `HIT_UNBIND_RATE_REACH` 门限进而 BIND 时，如果一个 TPROXY SYN 包恰好 hash 到同一 slot：

```
直连连接 UNBIND[slot X]：已积累 N 个包，接近 BIND 门限
    ↓
TPROXY SYN 包 hash → slot X
    ↓
tproxy_protection_v4: memset(FOE[X], 0)  ← 清零！
    ↓
直连连接计数归零，必须重新从 0 开始积累
    ↓
直连连接永远无法 BIND → 全走 CPU 慢路径 → 延迟
```

**为什么是偶发**：只有当 TPROXY 流量与直连流量发生 FOE slot hash 碰撞时才触发，这是小概率事件。

### 附加问题：ct->mark |= 0x8000 是死代码

其唯一消费者 `mtk_hnat_tproxy_connmark_check_v4()` 已于 commit `8fb160ffb5` 删除，继续写入 `ct->mark` 是无用开销，且在某些 CONNMARK 路径下有泄漏风险。

## 修复

### 修复 1（根本修复）：对 UNBIND 状态直接返回，不清零 FOE

```c
// 修复前：无论 BIND/UNBIND 都 memset
memset(entry, 0, sizeof(struct foe_entry));
if (foe_state == BIND) { hnat_cache_ebl(1); }

// 修复后：只在 BIND 时才需要驱逐
if (foe_state != BIND) {
    goto done;  // UNBIND: 没有 ASIC 状态需要驱逐，直接返回
}
// 只有 BIND 状态才执行：
memset(entry, 0, sizeof(struct foe_entry));
hnat_cache_ebl(1);
done:
```

**理由**：
- UNBIND 状态：FOE slot 无 ASIC 可见状态，无需清零
- BIND 状态（ASIC sample path）：必须清零以阻止硬件继续加速 TPROXY 流量
- 不触碰 UNBIND slot，保护了 hash 碰撞的直连连接

### 修复 2（辅助修复）：移除 ct->mark |= 0x8000 写入

死代码清除 + 防范潜在 CONNMARK 泄漏。

## 安全性验证

| 维度 | 验证 | 结论 |
|------|------|------|
| TPROXY 安全性 | TPROXY 流量 FOE 永远是 UNBIND，goto done 直接跳过，无需清零 | ✅ 不变 |
| ASIC sample path | foe_state == BIND 时仍然 memset + hnat_cache_ebl | ✅ 保留 |
| 直连连接保护 | UNBIND slot 不再被清零，hash 碰撞时直连连接不受影响 | ✅ 修复 |
| 新引入问题 | goto 是标准 C，label 在函数内，语法正确；无内存/并发问题 | ✅ 无 |
