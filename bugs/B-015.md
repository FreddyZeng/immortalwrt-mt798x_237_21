# B-015: loadbalance grep $var 前缀匹配导致错误网关 IP

<!-- BID: B-015 | FID: F-QOS01 | CID: C-FQOS01-12 -->

## 症状

多 WAN 场景（pppoe-wan + pppoe-wan2）时，`loadbalance` 为路由表 200（pppoe-wan）配置  
了错误的网关 IP（可能取 pppoe-wan2 的网关），导致 WAN1 的流量路由失效或走错接口。

## 根因

```bash
# 错误代码（原始）
ipaddr=$(ip route show | grep default | grep $var | awk '{print $3}')
```

`grep $var` 是 substring 匹配：  
- `$var = "pppoe-wan"` 时，`grep pppoe-wan` 同时匹配 `pppoe-wan` 和 `pppoe-wan2` 路由行  
- 若 `pppoe-wan2` 路由行先出现，`awk '{print $3}'` 取 pppoe-wan2 的网关  
- `ip route add default via <pppoe-wan2网关> dev pppoe-wan table 200` → 路由表污染

## 修复

```bash
# 修复后（精确接口路由查询）
ipaddr=$(ip route show default dev $var 2>/dev/null | awk 'NR==1 {print $3}')
```

`ip route show default dev $var` 只显示指定接口的默认路由，不会误匹配前缀接口名。  
同时补充所有 `iptables -D` 操作的 `2>/dev/null`，避免首次运行时的 stderr 噪声。

- `package/mtk/applications/luci-app-eqos-mtk/root/usr/sbin/loadbalance` — 第 20、40 行
